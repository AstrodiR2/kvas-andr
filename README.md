# Квас — Android-приложение (этапы 1–3)

Нативный проект на Kotlin + Jetpack Compose, без WebView. `applicationId` / namespace: `com.dimonchik.kvas`. HTML-макет использован как визуальный референс; его фиктивная логика не переносилась как настоящая.

## Что реализовано

### Этап 1 — онбординг
- Семь экранов с анимацией перехода вперёд/назад.
- Настоящие системные запросы Android для уведомлений и исключения оптимизации батареи; объявлено Termux `RUN_COMMAND` permission.
- Копирование команды настройки Termux, запуск Termux, обработка `kvas://setup-complete` и показ ошибки при возвращении без сигнала.
- Установка Pi 1.4.0 через Termux RUN_COMMAND с callback-результатом.

### Этап 2 — чат
- Нативный чат, пустое состояние, автогенерация короткого названия после первого ответа.
- Сохранение/поиск/открытие последних чатов; локальная история приложения синхронизируется в `~/.kvas/chats.json`, если Termux RUN_COMMAND разрешён.
- Проверка OpenAI-совместимого HTTPS API-ключа реальным запросом моделей; ключ хранится в Android Keystore-backed encrypted preferences.
- Выбор провайдера/модели, effort, размер контекста при наличии метаданных от провайдера.
- Пикеры Android для фото и файлов; текстовые файлы и изображения передаются модели в пределах заданных ограничений.
- Реальное чтение папок Termux под `$HOME`, выбор рабочей папки; пути файловых тулов проверяются и не должны выходить за неё, включая проверку symlink.
- Видимые план задач и список фоновых задач; остановка фоновой задачи требует подтверждения.

### Этап 3 — агент и инструменты
- Ограниченный цикл вызова tools для OpenAI-совместимых моделей: чтение/поиск/создание/редактирование файлов, папки, передача файла, план, вопросы пользователю, память, веб-поиск/загрузка и ограниченные локальные команды.
- Инструменты по умолчанию требуют подтверждения; есть настройки «Спрашивать», «Всегда разрешать», «Никогда» и общий режим для всех. Shell-команды проходят allowlist; операции с файлами ограничены выбранным workspace.
- Лента действий с анимацией текущего шага, иконками, простым diff с раскрытием; фоновые процессы можно остановить с подтверждением.
- Интерактивный виджет уточняющих вопросов, включая множественный выбор и последовательность до трёх вопросов.
- Markdown-рендерер с заголовками, списками, inline emphasis и блоками кода с базовой подсветкой; просмотр файлов, копирование, сохранение, экспорт текста в MD/PDF.
- Лайк/дизлайк, копирование/поделиться, контекстная карточка, `/models`, `/compact`, `/agents`, `/goal`, `/plan`, `/undo`, `/diff`, `/export`, `/cost`, `/context`, `/memory`.
- Локальная долгосрочная память; секреты и API-ключи отфильтровываются перед записью. Переключатель памяти влияет на её передачу в контекст и доступность инструмента сохранения.
- Добавлен GitHub Actions workflow для сборки debug APK.

## Ограничения этой версии

Это существенная реализация этапов 2–3, но не финальная проверенная сборка. В текущей среде не установлены Gradle и Android SDK, поэтому я не смог выполнить Kotlin/Compose-компиляцию или проверить приложение на устройстве. Для реального использования нужен прогон workflow/сборки и исправление ошибок, если окружение их выявит.

Оставшиеся пункты, которые нельзя честно считать завершёнными:
- `/agents` пока показывает заглушку; дочерние агенты не реализованы.
- Уведомления о завершении работы/вопросе агентом не отправляются.
- Экран настроек ещё не содержит полный каталог разрешений Termux:API, переключение темы/шрифта и тактильный отклик.
- Разметка Markdown и подсветка кода базовые (без полноценного рендеринга таблиц/языковых грамматик).
- Diff упрощённый; последовательные правки одного файла пока не объединяются в один элемент ленты.
- Подсчёт стоимости невозможен без тарифов провайдера; размер контекста неизвестен, когда API не отдаёт его.
- Чаты синхронизируются в `~/.kvas`, но лента действий, состояние фоновых задач и содержимое вложений не архивируются туда как полная резервная копия.
- Список bash-команд намеренно ограничен локальными чтением/тестами/сборкой; произвольные shell-команды и установка зависимостей требуют отдельного безопасного расширения.
- Просмотр бинарных файлов ограничен карточкой/сохранением; отправляемые агентом бинарные вложения ограничены 1 MiB.

## Сборка

Нужны JDK 17, Android SDK Platform 35 и Gradle 8.9+. В корне проекта:

```sh
gradle :app:assembleDebug
```

GitHub Actions (`.github/workflows/android.yml`) собирает APK при push, pull request, тегах `v*.*.*` и вручную; результат загружается как artifact `kvas-debug-apk`.

Для Termux-функций требуется установленный Termux с включённым `allow-external-apps=true` и выданным приложению разрешением RUN_COMMAND. Android управляет этим разрешением отдельно от обычных runtime permissions, поэтому доступность экрана выдачи зависит от версии Android/Termux.
